# Dashboard tickets

This repository contains the ticket views, routes, interface, data-access layer and ticket-specific Django models for the [CCI Django dashboard](https://github.com/CCI-GU-Sweden/Dashboard-django). It is not a standalone application: the core owns login, shared permissions and audit.

The package uses core user and audit models and existing PostgreSQL ticket tables. Its five Django models keep their historical `accounts_*` table names, which are also referenced by SQL. The paired core and module migrations transfer Django model state without changing those tables, verify the required tables/columns exist, and move existing content type records without changing their IDs or linked permissions. Conflicting content types stop migration for review. Run these paired migrations once, with a backup and a verified rollback plan, before starting the new application; never deploy the module migration without its matching core migration. The historical core migrations still create the five empty legacy tables on a fresh database even if tickets are disabled; eliminating that dependency needs a separately reviewed migration-history strategy. Module views enforce permissions before calling the data layer. The overview scopes researcher statistics to tickets explicitly linked to that researcher.

Set `DASHBOARD_TICKETS_ENABLED=0` in the core before startup to disable ticket routes and overview. Existing ticket data and researcher permissions are retained. The ticket schema and integrations currently live in the existing deployment and collector repositories; setup, schema collision checks and any needed integration workloads will be brought into this repository in a later step. The image validation code uses Pillow. Existing code copyright is retained in [CORE_LICENSE](CORE_LICENSE); this repository is MIT licensed. Run frontend tests from this checkout with `node --test tests/*.test.js`.
